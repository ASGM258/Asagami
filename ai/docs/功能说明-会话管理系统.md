# 会话管理系统功能说明

## 📖 概述

会话管理系统为用户与AI的对话提供持久化存储和多轮对话支持。

当前实现采用**双层持久化**：

| 数据 | 存储 | 说明 |
|------|------|------|
| 会话元数据（标题、归属用户、软删除） | PostgreSQL `chat_sessions` 表 | 业务语义 |
| 对话状态与消息 | LangGraph 检查点表 | 由 `PostgresSaver` 自动读写 |

会话标识 `session_id` **同时作为 LangGraph 的 `thread_id`**，两者一一对应，因此多轮对话的上下文由检查点自动恢复，无需手工拼装历史消息。

> 与旧版的区别：旧版用 MySQL 的 `chat_sessions` + `chat_messages` 两张表，每轮由业务代码手工 `save_message()` 写库。现在消息不再进入业务表，而是随对话状态进入检查点。

## ✨ 核心特性

### 1. 会话管理
- **创建会话**：自动生成唯一 `session_id`（`session_` + 16 位十六进制）
- **标题管理**：支持自定义，或自动取首个问题的前 20 个字符
- **会话列表**：按用户查询，按最后活跃时间倒序
- **删除机制**：软删除（保留数据，接口视为不存在）与彻底删除（连检查点一并清理）

### 2. 消息存储
- **结构化消息**：状态中保存的是 `HumanMessage` / `AIMessage` / `ToolMessage` 对象
- **自动持久化**：一轮对话结束后整份状态写入检查点，无需手工写库
- **历史回放**：读取时过滤工具调用的中间消息，仅暴露用户与 AI 的对话
- **顺序保证**：按时间正序返回
- **稳定ID**：`message_id` 由 `MessageIdMiddleware` 写入并随消息持久化

### 3. 数据完整性
- **单一事实来源**：会话状态只有检查点一条写入路径
- **存在性判断**：一律以元数据表为准，而非检查点是否存在
  - 刚创建、尚未对话的空会话可被正常列出与访问
  - 软删除后 `get_session_info` 自然返回空
- **级联清理**：硬删除时按 `thread_id` 一并清理检查点相关表

## 🗄️ 数据库设计

### 1. 会话元数据表 (chat_sessions)

```sql
CREATE TABLE IF NOT EXISTS chat_sessions (
    session_id VARCHAR(64)  PRIMARY KEY,
    user_id    BIGINT       NOT NULL,
    title      VARCHAR(255) NOT NULL DEFAULT '新会话',
    created_at TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    is_deleted SMALLINT     NOT NULL DEFAULT 0
);

CREATE INDEX IF NOT EXISTS idx_chat_sessions_user_id    ON chat_sessions (user_id);
CREATE INDEX IF NOT EXISTS idx_chat_sessions_created_at ON chat_sessions (created_at);
```

**字段说明**：

| 字段 | 说明 |
|------|------|
| `session_id` | 格式为 `session_` + 16 位十六进制；同时是 LangGraph `thread_id` |
| `user_id` | 归属用户ID，用于数据隔离 |
| `title` | 会话标题，默认「新会话」，可由前端更新 |
| `created_at` | 创建时间 |
| `updated_at` | 最后活跃时间，每轮对话后刷新 |
| `is_deleted` | 软删除标记，0=正常，1=已删除 |

> 与旧版相比去掉了自增 `id` 列——`session_id` 本身已可作主键，避免冗余。

### 2. 检查点表（LangGraph 自动创建）

由 `PostgresSaver.setup()` 在服务启动时创建，**无需手工执行**：

| 表 | 内容 |
|----|------|
| `checkpoints` | 每个检查点的状态快照 |
| `checkpoint_blobs` | 序列化后的通道数据（含消息本体） |
| `checkpoint_writes` | 中间写入结果 |
| `checkpoint_migrations` | 迁移版本记录 |

对话消息即保存在 `checkpoint_blobs` 中，按 `thread_id`（= `session_id`）组织。

### 3. 初始化步骤

```bash
# 1. 创建数据库
psql -U postgres -c "CREATE DATABASE anime_ai;"

# 2. 创建会话元数据表（可选，程序启动时会幂等创建）
psql -U postgres -d anime_ai -f init_conversations.sql

# 3. 配置 ai/.env
#    AI_DATABASE_URL=postgresql://postgres:密码@localhost:5432/anime_ai
```

## 🔌 API接口详解

所有接口的响应体字段与重构前**完全一致**。

### 1. 创建新会话

**接口地址**：`POST /api/session/create`

**请求参数**：

```json
{
  "user_id": 1,
  "title": "会话标题"
}
```

**响应格式**：

```json
{
  "success": true,
  "message": "会话创建成功",
  "timestamp": 1720540800.123,
  "data": {
    "session_id": "session_a1b2c3d4e5f6g7h8",
    "title": "会话标题"
  }
}
```

**说明**：`title` 可选，缺省为「新会话」。创建后会话立即出现在列表中，即使尚未开始对话。

---

### 2. 获取用户会话列表

**接口地址**：`GET /api/sessions?user_id=1&limit=50`

**查询参数**：

| 参数 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `user_id` | 是 | — | 用户ID |
| `limit` | 否 | 50 | 返回数量限制 |

**响应格式**：

```json
{
  "success": true,
  "message": "获取会话列表成功",
  "timestamp": 1720540800.123,
  "data": {
    "sessions": [
      {
        "session_id": "session_a1b2c3d4e5f6g7h8",
        "title": "我的追番历史怎么样？",
        "created_at": "2026-10-08 11:18:20",
        "updated_at": "2026-10-08 11:20:35"
      }
    ],
    "count": 1
  }
}
```

**说明**：`created_at` / `updated_at` 为 `YYYY-MM-DD HH:MM:SS` 字符串；已软删除的会话不在列表中。

---

### 3. 获取会话历史消息

**接口地址**：`GET /api/session/{session_id}/messages?limit=100`

**响应格式**：

```json
{
  "success": true,
  "message": "获取消息成功",
  "timestamp": 1720540800.123,
  "data": {
    "session_id": "session_a1b2c3d4e5f6g7h8",
    "messages": [
      {
        "message_id": "msg_1a2b3c4d5e6f7g8h",
        "role": "user",
        "content": "我的追番历史怎么样？",
        "created_at": "2026-10-08 11:18:20"
      },
      {
        "message_id": "msg_9i8h7g6f5e4d3c2b",
        "role": "assistant",
        "content": "根据您的记录……",
        "created_at": "2026-10-08 11:18:20"
      }
    ],
    "count": 2
  }
}
```

**重要说明**：

- 消息来源为**检查点**，非业务表
- 工具调用产生的中间消息（`ToolMessage`）与空内容消息会被过滤，只保留 `user` / `assistant`
- 单次最多从检查点读取 1000 条，再按 `limit` 截取**最近**若干条
- 会话不存在或已软删除时返回 `404` / `SESSION_NOT_FOUND`

---

### 4. 更新会话标题

**接口地址**：`PUT /api/session/{session_id}/title`

**请求参数**：

```json
{ "title": "新标题" }
```

**响应格式**：

```json
{
  "success": true,
  "message": "标题更新成功",
  "timestamp": 1720540800.123,
  "data": { "session_id": "session_a1b2c3d4e5f6g7h8" }
}
```

---

### 5. 删除会话

**接口地址**：`DELETE /api/session/{session_id}?hard=false`

| 参数 | 默认 | 说明 |
|------|------|------|
| `hard` | false | false=软删除；true=彻底删除（含检查点消息） |

**响应格式**：

```json
{
  "success": true,
  "message": "会话已删除",
  "timestamp": 1720540800.123,
  "data": { "session_id": "session_a1b2c3d4e5f6g7h8" }
}
```

**两种删除的区别**：

| 方式 | 元数据 | 检查点消息 | 可恢复 |
|------|--------|-----------|--------|
| 软删除 | 保留（`is_deleted=1`） | 保留 | 可（改回 0） |
| 彻底删除 | 删除行 | 删除 | 否 |

## 💻 代码实现

### 1. 会话服务（`app/services/session_service.py`）

| 方法 | 职责 |
|------|------|
| `create_session(user_id, title)` | 生成 `session_xxx`，写入元数据 |
| `list_sessions(user_id, limit)` | 按 `updated_at` 倒序返回 |
| `require_session(session_id)` | 不存在则抛 `SessionNotFoundError`（404） |
| `update_title(session_id, title)` | 更新标题 |
| `delete_session(session_id, hard)` | 软删除 / 彻底删除 |
| `get_messages(session_id, limit)` | **从检查点**读取并映射为契约格式 |
| `touch(session_id)` | 刷新会话活跃时间 |

### 2. 从检查点读取消息

```python
def get_messages(self, session_id: str, limit: int = 100) -> list[dict]:
    agent = self._agent_factory.agent
    snapshot = agent.get_state(thread_config(session_id))

    messages = list(snapshot.values.get("messages", [])) if snapshot else []
    created_at = format_timestamp(snapshot.created_at) if snapshot else None

    formatted = [
        item for item in (
            self._format_message(m, created_at) for m in messages
        ) if item is not None
    ]
    return formatted[-limit:] if limit and limit > 0 else formatted

@staticmethod
def _format_message(message, created_at) -> dict | None:
    if isinstance(message, HumanMessage):
        role = "user"
    elif isinstance(message, AIMessage):
        role = "assistant"
    else:
        return None                      # 过滤 ToolMessage

    if not isinstance(message.content, str) or not message.content.strip():
        return None                      # 过滤工具调用的空内容消息

    return {
        "message_id": message.additional_kwargs.get("message_id") or message.id or "",
        "role": role,
        "content": message.content,
        "created_at": created_at,
    }
```

**注意事项**：

- `snapshot.created_at` 是 ISO 字符串（`2026-10-08T11:18:20.367616+00:00`），必须经 `format_timestamp()` 转换
- `message_id` 优先取 `additional_kwargs` 中由中间件写入的业务ID，保证与当轮流式响应一致

## 🔄 典型工作流程

### 场景1：新用户开始对话

```
前端 POST /api/anime-chat-stream  {"question": "...", "user_id": 1}
        ↓
chat_service._resolve_session()
        ↓
未传 session_id 且有 user_id → 创建会话
        ↓
title = 问题前20个字符（超长则加 "..."）
        ↓
session_id = session_xxxx（同时作为 thread_id）
        ↓
Agent 流式产出 content 事件
        ↓
检查点写入完整对话状态
        ↓
end 事件返回 {session_id, message_id}
```

### 场景2：继续历史对话

```
前端 POST /api/anime-chat-stream  {"question": "...", "session_id": "session_xxx"}
        ↓
session_service.require_session() 校验存在性（元数据表）
        ↓
user_id 以元数据表记录为准（防止越权）
        ↓
agent.astream(state, {"configurable": {"thread_id": session_id}})
        ↓
检查点自动恢复历史消息 → 模型获得完整上下文
        ↓
新增消息追加写入检查点
```

### 场景3：打开历史会话

```
前端 GET /api/session/{id}/messages
        ↓
require_session() 校验存在性
        ↓
agent.get_state({"configurable": {"thread_id": id}})
        ↓
过滤 ToolMessage 与空内容 → 映射为 {message_id, role, content, created_at}
        ↓
截取最近 limit 条返回
```

### 场景4：删除会话

```
前端 DELETE /api/session/{id}?hard=false
        ↓
require_session() 校验存在性
        ↓
hard=false → UPDATE chat_sessions SET is_deleted = 1
hard=true  → DELETE 元数据行 + 清理 checkpoints / checkpoint_blobs / checkpoint_writes
```

## 🔐 安全与隐私

### 1. 数据隔离

- 会话列表严格按 `user_id` 过滤
- 继续会话时 `user_id` **取自元数据表**而非请求体，避免拼接他人 `session_id` 越权读取

### 2. SQL注入防护

```python
# ✅ 正确: 参数化查询
cursor.execute("SELECT * FROM chat_sessions WHERE session_id = %s", (session_id,))

# ❌ 错误: 字符串拼接
cursor.execute(f"SELECT * FROM chat_sessions WHERE session_id = '{session_id}'")
```

### 3. 敏感信息保护

- 系统提示词要求模型不在回答中泄露完整 ID 等敏感信息
- 工具返回数据前会剔除内部主键（如 `user_anime.id`）

### 4. 访问控制建议

当前接口未校验 JWT。前端已携带 `Authorization` 头，如需启用，可增加依赖：

```python
async def require_auth(authorization: str = Header(None)) -> int:
    # 解析 Bearer Token → 返回 user_id
    # 失败抛 BusinessError(error_code="UNAUTHORIZED", http_status=401)
    ...
```

## 📊 性能监控

### 关键指标

| 指标 | 说明 |
|------|------|
| 会话创建耗时 | 单条 INSERT，应 <10ms |
| 消息读取耗时 | 检查点查询，随会话长度增长 |
| 硬删除耗时 | 需清理多张检查点表 |

### 优化建议

- 超长会话建议依赖 `limit` 分页读取，而非一次性全量加载
- 定期归档长期不活跃的会话（可扩展 `is_deleted` 之外的归档标记）

## 🚀 扩展方向

### 1. 会话归档
为长期不活跃会话增加 `archived_at`，列表默认隐藏。

### 2. 消息搜索
检查点中的消息不易做全文检索，如需搜索可引入独立的检索索引表。

### 3. 会话统计
基于 `created_at` / `updated_at` 统计用户活跃度与平均对话轮次。

### 4. 多设备同步
会话状态已在服务端集中存储，天然支持多端读取；如需实时推送可加 WebSocket。

### 5. 检查点裁剪
LangGraph 提供 `delete_thread()` 与裁剪接口，可为超长会话保留最近 N 轮以控制存储增长。
