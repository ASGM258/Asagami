# 追番与收藏功能文档

## 📋 功能概述

本模块提供用户追番管理和角色收藏功能，包括更新追番状态、查询追番历史、喜欢/取消喜欢角色等。支持多种观看状态管理，实时同步用户操作，并集成缓存优化查询性能。

## 🔧 技术实现

### 核心技术栈
- **MyBatis** - ORM 框架
- **Redis** - 追番列表缓存
- **UserContext** - 用户身份获取
- **事务管理** - 数据一致性保证

### 架构设计
```
客户端 → UserAnimeController → UserAnimeService → UserAnimeMapper → Database
                                    ↓
                              CacheService
                                    ↓
                                  Redis
```

## 📡 API 接口详情

### 1. 更新追番状态

**接口地址**: `PUT /api/anime/user/update`

**请求头**:
```
Authorization: Bearer <token>
```

**请求参数**:
```json
{
  "animeId": 1,                    // 动漫ID，必填
  "watchStatus": "WATCHING",       // 观看状态，必填
  "currentEpisode": 10,            // 当前观看集数，可选
  "score": 9                       // 评分（1-10），可选
}
```

**观看状态枚举**:
- `PLAN_TO_WATCH` - 想看
- `WATCHING` - 在看
- `COMPLETED` - 看完
- `ON_HOLD` - 搁置
- `DROPPED` - 弃番

**响应示例**:
```json
{
  "code": 200,
  "message": "更新成功",
  "data": true
}
```

**业务逻辑**:
1. 验证用户登录状态
2. 验证动漫 ID 是否存在
3. 验证观看状态合法性
4. 检查是否已存在记录
   - 存在：UPDATE 更新状态、集数、评分
   - 不存在：INSERT 新增记录
5. 清除相关缓存
   - 动漫详情缓存（所有用户）
   - 用户追番历史缓存（该用户）
   - 列表分页缓存（该用户）

**错误码**:
- `401` - 未登录
- `400` - 参数错误
- `404` - 动漫不存在

---

### 2. 查询追番历史

**接口地址**: `GET /api/anime/user/history`

**请求头**:
```
Authorization: Bearer <token>
```

**请求参数**:
```
status: WATCHING     // 观看状态过滤（可选）
pageNum: 1           // 页码，默认1
pageSize: 10         // 每页数量，默认10
```

**响应示例**:
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 50,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 5,
    "list": [
      {
        "animeId": 1,
        "mainId": 16498,
        "title": "Shingeki no Kyojin",
        "chineseTitle": "进击的巨人",
        "coverImage": "https://cdn.myanimelist.net/images/anime/10/47347.jpg",
        "watchStatus": "WATCHING",
        "currentEpisode": 10,
        "totalEpisodes": 25,
        "score": 9,
        "updateTime": "2026-07-09T15:30:00"
      }
    ]
  }
}
```

**业务逻辑**:
1. 验证用户登录状态
2. 生成缓存键（包含用户ID和状态）
3. 尝试从 Redis 获取缓存
4. 缓存未命中时查询数据库
   - 联表查询动漫信息
   - 按更新时间倒序排列
5. 设置缓存并返回结果

**缓存策略**:
- 缓存键格式：`anime:user:history:{userId}:{status}:{pageNum}:{pageSize}`
- 过期时间：30 分钟
- 清除时机：更新追番状态后清除对应用户的分页缓存

**错误码**:
- `401` - 未登录

### 3. 更新喜欢角色状态

**接口地址**: `POST /api/character/favorite/update`

**请求头**:
```
Authorization: Bearer <token>
```

**请求参数**:
```json
{
  "characterId": 1,           // 角色ID，必填
  "favoriteStatus": 1         // 喜欢状态：1-喜欢，0-取消喜欢
}
```

**响应示例**:
```json
{
  "code": 200,
  "message": "喜欢成功",
  "data": true
}
```

**业务逻辑**:
1. 验证用户登录状态
2. 验证角色 ID 是否存在
3. 验证喜欢状态合法性（0 或 1）
4. 检查是否已存在记录
   - 存在：UPDATE 更新 favorite_status
   - 不存在：INSERT 新增记录（favorite_status = 1）
5. 清除相关缓存
   - 角色详情缓存（所有用户）
   - 角色列表分页缓存（该用户）

**特殊处理**:
- 不直接删除记录，而是更新状态字段
- 保留历史记录便于数据分析
- 使用唯一索引防止重复记录

**错误码**:
- `401` - 未登录
- `400` - 参数错误
- `404` - 角色不存在

## 🗄️ 数据库设计

### user_anime 表（用户追番表）

```sql
CREATE TABLE `user_anime` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `anime_id` BIGINT NOT NULL COMMENT '动漫ID',
  `main_id` INT DEFAULT NULL COMMENT 'MAL ID',
  `watch_status` VARCHAR(20) NOT NULL COMMENT '观看状态',
  `current_episode` INT DEFAULT 0 COMMENT '当前观看集数',
  `score` INT DEFAULT NULL COMMENT '评分（1-10）',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_anime` (`user_id`, `anime_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_anime_id` (`anime_id`),
  KEY `idx_watch_status` (`watch_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户追番表';
```

**唯一索引**:
- `uk_user_anime` - 防止同一用户对同一动漫重复追番

**字段说明**:
- `watch_status` - 枚举值：PLAN_TO_WATCH, WATCHING, COMPLETED, ON_HOLD, DROPPED
- `current_episode` - 当前观看集数，用于断点续播
- `score` - 用户评分，1-10 分

---

### user_favorite_character 表（用户喜欢角色表）

```sql
CREATE TABLE `user_favorite_character` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `character_id` BIGINT NOT NULL COMMENT '角色ID',
  `favorite_status` TINYINT NOT NULL DEFAULT 1 COMMENT '喜欢状态：1-喜欢，0-取消',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_character` (`user_id`, `character_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_character_id` (`character_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户喜欢角色表';
```

**唯一索引**:
- `uk_user_character` - 防止同一用户对同一角色重复喜欢

**字段说明**:
- `favorite_status` - TINYINT 类型，1 表示喜欢，0 表示取消喜欢
- 不直接删除记录，保留历史轨迹

## 🔍 查询优化

### 1. 联表查询追番列表

```xml
<select id="selectUserAnimeHistory" resultMap="UserAnimeResultMap">
  SELECT 
    ua.anime_id,
    ua.main_id,
    a.title,
    nm.chinese_title,
    a.cover_image,
    ua.watch_status,
    ua.current_episode,
    a.episodes as total_episodes,
    ua.score,
    ua.update_time
  FROM user_anime ua
  INNER JOIN anime a ON ua.anime_id = a.id
  LEFT JOIN anime_name_mapping nm ON a.id = nm.anime_id
  WHERE ua.user_id = #{userId}
  <if test="status != null and status != ''">
    AND ua.watch_status = #{status}
  </if>
  ORDER BY ua.update_time DESC
</select>
```

**优势**:
- 一次查询获取追番记录和动漫信息
- 避免 N+1 查询问题
- 支持按状态过滤

### 2. 批量查询喜欢状态

在角色列表查询时联表获取喜欢状态：

```xml
<select id="selectCharacterPage" resultMap="CharacterSimpleDTOResultMap">
  SELECT 
    c.id,
    c.mal_id,
    c.name,
    c.name_japanese,
    c.image_url,
    c.anime_title,
    ufc.favorite_status
  FROM character c
  LEFT JOIN user_favorite_character ufc 
    ON c.id = ufc.character_id AND ufc.user_id = #{userId}
  <where>
    <if test="name != null and name != ''">
      AND (c.name LIKE CONCAT('%', #{name}, '%') 
           OR c.name_japanese LIKE CONCAT('%', #{name}, '%'))
    </if>
  </where>
  ORDER BY c.create_time DESC
</select>
```

**优势**:
- 列表查询时直接获取喜欢状态
- 避免逐个查询
- 提升响应速度

## ⚠️ 注意事项

### 数据一致性

1. **唯一索引约束**
   - `user_anime.uk_user_anime` - 防止重复追番
   - `user_favorite_character.uk_user_character` - 防止重复喜欢
   - 依赖数据库层面去重

2. **事务管理**
   - 插入/更新操作使用事务
   - 失败时回滚
   - 保证原子性

3. **缓存同步**
   - 数据更新后立即清除相关缓存
   - 使用通配符删除模式缓存
   - 避免脏数据

## 📝 常见问题

### Q1: 如何处理并发更新追番状态？

**A**: 
- 使用唯一索引防止重复插入
- 使用 `ON DUPLICATE KEY UPDATE` 语句
- 数据库层面保证一致性

### Q2: 为什么喜欢状态不直接删除记录？

**A**: 
- 保留历史记录便于数据分析
- 避免频繁插入删除
- 可以统计用户的喜好变化

### Q3: 如何实现追番进度同步？

**A**: 
- 每次观看更新 current_episode
- 可扩展 watch_history 表记录详细进度
- 前端上报观看时间点

### Q4: 如何推荐相似动漫？

**A**: 
- 基于用户追番记录的 genre
- 基于相同 studios 的动漫
- 协同过滤算法（看的人也看了）
