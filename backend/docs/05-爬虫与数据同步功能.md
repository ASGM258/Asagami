# 爬虫与数据同步功能文档

## 📋 功能概述

本模块提供从 MyAnimeList 自动抓取动漫和角色数据的功能，包括单个动漫抓取、批量抓取、当季新番抓取、智能更新等。支持异常处理、速率限制、缓存清除等特性，确保数据同步的稳定性和效率。

> ✅ **数据源迁移已完成**：原 Jikan API（`api.jikan.moe`）已不可用（连接超时），
> **当季新番、动漫详情、角色抓取三条链路均已迁移到 AniList GraphQL**。
> AniList 免费、无需密钥，且动漫侧响应带 `idMal`（即 MAL ID），
> 因此动漫相关的 MAL ID 匹配逻辑得以完整保留。
>
> ⚠️ 唯一的语义变化在角色侧：**AniList 的角色对象不提供 MAL ID**，
> 因此角色标识改用 `anime_character.anilist_id` 列（原 `mal_id` 仅保留历史数据），
> 需执行 `migrate_character_anilist.sql`。

## 🔧 技术实现

### 核心技术栈
- **RestTemplate** - HTTP 客户端（Spring 单例配置）
- **当季新番数据源**：AniList GraphQL（可插拔，见 `SeasonalAnimeSource`）
- **动漫详情数据源**：AniList GraphQL（可插拔，见 `AnimeDetailSource`）
- **角色数据源**：AniList GraphQL（可插拔，见 `CharacterDetailSource`）
- **Jackson** - JSON 解析
- **Spring Scheduler** - 定时任务
- **Redis** - 缓存清除

### 架构设计
```
Controller → Service → SeasonalAnimeSource（接口）
                            ↓
              AniListSeasonalAnimeSource（GraphQL）
                            ↓
                   SeasonalAnimeItem（归一化 DTO）
                            ↓
                   去重 → 实体映射 → 批量入库
                            ↓
              未匹配项 → AnimeDetailSource（接口）
                            ↓
              AniListAnimeDetailSource（GraphQL）
                            ↓
                   AnimeDetail（归一化 DTO）→ anime 表

角色链路：
Service → CharacterDetailSource（接口）
              ↓
   AniListCharacterSource（GraphQL）
              ↓
   CharacterDetail（归一化 DTO）→ anime_character 表
```

### 三个数据源的对比

| 数据源接口 | 实现 | 入口标识 | 说明 |
|---|---|---|---|
| `SeasonalAnimeSource` | `AniListSeasonalAnimeSource` | 季度+年份 | 分页，返回 MAL ID |
| `AnimeDetailSource` | `AniListAnimeDetailSource` | **MAL ID** | `Media(idMal:)`，入口未变 |
| `CharacterDetailSource` | `AniListCharacterSource` | **AniList ID** | AniList 无角色 MAL ID |

> 角色侧的两点改进：
> 1. AniList 的角色列表接口**直接返回完整字段**（简介/生日/别名/收藏数），
>    不再需要「先取列表页、再逐个请求详情」——原 Jikan 实现每个角色间隔 3 秒，
>    抓 50 个角色就要 2.5 分钟以上
> 2. 去重键改为 `anilist_id`，与 `mal_id` 职责分离
```

## 📡 API 接口详情

### 1. 抓取单个动漫

**接口地址**: `POST /anime/scraper/fetch/{malId}`

**请求参数**:
```
malId: 16498             // MyAnimeList 动漫ID，路径参数
```

**响应示例**:
```json
{
  "code": 200,
  "message": "抓取成功",
  "data": 1                // 保存后的动漫ID
}
```

**业务逻辑**:
1. 通过 `AnimeDetailSource` 数据源按 MAL ID 获取动漫数据
   （**当前实现为 AniList GraphQL**，`Media(idMal: Int)`；原 Jikan API 已不可用）
2. 归一化为 `AnimeDetail` DTO（标题/封面/简介/集数/状态/开播日期/类型/评分）
3. 映射到 Anime 实体
4. 查重：先按 `title_jp` 精确匹配，再退回 `title`
   - 存在：直接返回已有 ID（不重复插入）
   - 不存在：INSERT 新增
5. 清除动漫详情与列表分页缓存
6. 返回保存后的动漫 ID

**错误处理**:
- 404 错误：数据源返回 `AnimeNotFoundException`，消息含 "404"，
  异步补抓据此判定**无需重试**
- 5xx 错误：抛异常，由上游按需重试
- 网络错误：记录日志，抛出异常

**速率限制**:
- AniList 限制：约 90 请求/分钟（原 Jikan 为每秒 3 次）
- 调用方（补抓队列）每次请求间隔 400ms

---

### 2. 批量抓取动漫

**接口地址**: `POST /anime/scraper/fetch/batch`

**请求参数**:
```
malIds: 16498,5114,1535  // MAL ID 列表，逗号分隔
```

**响应示例**:
```json
{
  "code": 200,
  "message": "批量抓取完成:\n✅ 成功: 2 个\n❌ 不存在: 1 个\n⚠️ 失败: 0 个\n\n详细结果:\n✅ MAL ID 16498 -> 动漫ID 1\n✅ MAL ID 5114 -> 动漫ID 2\n❌ MAL ID 1535 -> 不存在 (404)\n",
  "data": null
}
```

**业务逻辑**:
1. 解析 MAL ID 列表
2. 循环抓取每个动漫
3. 分类统计结果
   - ✅ 成功
   - ❌ 不存在（404）
   - ⚠️ 其他失败
4. 每次成功抓取后休眠 1 秒
5. 返回详细结果汇总

**异常处理**:
- 404 错误：标记为"不存在"，继续处理下一个
- 其他错误：标记为"失败"，继续处理下一个
- 单个失败不影响整体流程

**性能优化**:
- 成功后休眠 1 秒避免速率限制
- 失败后立即继续不休眠
- 异步处理可扩展为队列模式

### 3. 抓取当季新番

**接口地址**: `POST /api/anime/scraper/seasonal/fetch`

**响应示例**:
```json
{
  "code": 200,
  "message": "抓取成功，共保存 25 条记录",
  "data": 25
}
```

**业务逻辑**:
1. 通过 `SeasonalAnimeSource` 数据源抓取当前季度新番
   （**当前实现为 AniList GraphQL**，原 Jikan API 已不可用，详见下方「当季新番数据源」）
2. 分页遍历数据源，直到 `hasNextPage` 为 false
3. 逐条归一化为排期实体（标题、封面、评分、集数、状态、更新星期）
4. 按 `title + dayOfWeek` 去重后批量写入 anime_schedule 表
5. 未能在 anime 表中匹配到记录的条目，以其 MAL ID 加入异步补抓队列
6. 返回保存数量

**数据存储**:
- 表：`anime_schedule`
- 唯一索引：`uk_schedule_title_week (title, dayOfWeek)`

**特殊处理**:
- 更新星期由数据源的「下一次放送时间」换算（Asia/Shanghai），落在 1-7
- 没有下一次放送时间的条目（已完结/未开播）`dayOfWeek` 为 null，前端按「待定」展示
- 评分统一为 10 分制（数据源若为百分制需除以 10），对应 `rating decimal(3,1)`

**接口地址**: `POST /api/anime/scraper/seasonal/refresh`

**响应示例**:
```json

  "message": "刷新成功，共保存 25 条记录",

2. 重新抓取当季新番
3. 插入最新数据
4. 返回保存数量

**使用场景**:

- 数据异常时重新抓取

**注意**:
- 会删除所有现有数据
- 生产环境谨慎使用

### 5. 智能更新当季新番

**接口地址**: `POST /api/anime/scraper/seasonal/smart-update`

**响应示例**:
```json
{
  "code": 200,
  "message": "智能更新成功，共保存 25 条记录",
  "data": 25
}
```

**业务逻辑**:
1. 获取当前年份和季度
2. 查询数据库中最后一条记录的年份和季度
3. 判断季度是否变更
   - **同一季度**：更新现有数据（UPDATE）
   - **不同季度**：清空旧数据，插入新数据
4. 调用 Jikan API 获取最新数据
5. 执行更新或插入操作
6. 清除相关缓存

**智能策略**:
```java
// 伪代码
if (currentYear == dbYear && currentSeason == dbSeason) {
    // 同一季度：更新现有数据
    updateExistingRecords();
} else {
    // 不同季度：清空后重新插入
    clearAllRecords();
    insertNewRecords();
}
```

**优势**:
- 避免不必要的数据清空
- 保留历史数据的完整性
- 自动适应季度切换

**定时任务**:
- 每天凌晨 00:00 自动执行
- 使用 Spring `@Scheduled` 注解
- Cron 表达式：`0 0 0 * * ?`

  `synopsis` TEXT COMMENT '剧情简介',
  `score` DECIMAL(3,2) DEFAULT NULL COMMENT '评分',
  `members` INT DEFAULT NULL COMMENT '收藏人数',
  `status` VARCHAR(50) DEFAULT NULL COMMENT '状态',

  `broadcast_time` TIME DEFAULT NULL COMMENT '播出时间',
  `producers` VARCHAR(1000) DEFAULT NULL COMMENT '制作公司（JSON数组）',
  `studios` VARCHAR(1000) DEFAULT NULL COMMENT '动画工作室（JSON数组）',

- `season` + `year` - 联合标识季度

**索引说明**:
- `UNIQUE KEY uk_main_id` - MAL ID 唯一索引
- `KEY idx_broadcast_day` - 按星期查询索引
- `KEY idx_season_year` - 按季度年份查询索引

#### 2. 获取当季新番（AniList GraphQL）

> ⚠️ **当季新番已从 Jikan API 迁移到 AniList**。Jikan（`api.jikan.moe`）当前不可用（连接超时），
> 而 MyAnimeList 官方 API v2 需要申请 Client ID 且对多数账号已关闭新注册。
> AniList 免费、无需密钥，且响应中带 `idMal`（即 MAL ID），因此可以直接复用
> 原有基于 MAL ID 的匹配与补抓逻辑。

**端点**: `POST https://graphql.anilist.co`

**请求体**（季度与年份作为 GraphQL 变量传入，避免字符串拼接）：

```json
{
  "query": "query ($page: Int, $perPage: Int, $season: MediaSeason, $seasonYear: Int) { Page(page: $page, perPage: $perPage) { pageInfo { total currentPage lastPage hasNextPage } media(season: $season, seasonYear: $seasonYear, type: ANIME, sort: POPULARITY_DESC) { id idMal title { native romaji } coverImage { extraLarge large medium } averageScore episodes status nextAiringEpisode { airingAt episode } } } }",
  "variables": { "page": 1, "perPage": 50, "season": "FALL", "seasonYear": 2026 }
}
```

**响应结构（节选）**:

```json
{
  "data": {
    "Page": {
      "pageInfo": { "total": 5000, "currentPage": 1, "lastPage": 416, "hasNextPage": true },
      "media": [
        {
          "id": 195516,
          "idMal": 61987,
          "title": {
            "native": "薬屋のひとりごと 第3期",
            "romaji": "Kusuriya no Hitorigoto 3rd Season"
          },
          "coverImage": { "extraLarge": "https://...", "large": "https://...", "medium": "https://..." },
          "averageScore": 85,
          "episodes": 12,
          "status": "RELEASING",
          "nextAiringEpisode": { "airingAt": 1791554400, "episode": 2 }
        }
      ]
    }
  }
}
```

**字段映射（`AniListSeasonalAnimeSource`）**:

| AniList 字段 | 映射到 | 说明 |
|---|---|---|
| `idMal` | malId | 用于补齐 anime 表记录；缺失时仅入库展示 |
| `title.native` | title | 日文原名，用于匹配 `anime.title_jp`；缺失时退化为 `romaji` |
| `coverImage.extraLarge` | coverImage | 依次降级到 `large` / `medium` |
| `averageScore` | rating | **0-100 需 ÷10** 转成 10 分制（`rating` 为 `decimal(3,1)`） |
| `episodes` | episodes | 可能为 null，按 0 处理 |
| `status` | status | `FINISHED` / `CANCELLED` → 1（完结），其余 → 0（连载中） |
| `nextAiringEpisode.airingAt` | dayOfWeek / updateTime | Unix 秒 → Asia/Shanghai 的星期几与 HH:mm |

**季节参数**:
- `season`: `WINTER`(1-3月) / `SPRING`(4-6月) / `SUMMER`(7-9月) / `FALL`(10-12月)
- `seasonYear`: 当前年份
- 两者均由服务按 `Asia/Shanghai` 时区自动计算

**分页处理**:
- 默认每页 50 条（AniList 上限 50，配置项 `scraper.seasonal.page-size`）
- 由 `pageInfo.hasNextPage` 驱动翻页，页间隔 1 秒
- 另有 `MAX_PAGES=120` 作为安全阀，仅防分页异常导致死循环
- `pageInfo.total` 恒为 5000（AniList 的分页上限，并非真实季度总数），故不能据其判断结束

#### 3. 标题匹配策略（续作后缀归一化）

数据源返回的多为**续作标题**（`作品 第3期`、`作品 Season 2`、`作品：副标题`），
而 `anime` 表存的是**基础标题**，直接精确匹配几乎全部落空。

`SeasonalScraperServiceImpl` 因此采用三轮匹配：

1. `title_jp` / `title` 精确匹配
2. 剥离续作后缀后精确匹配
3. 双向前缀匹配（要求 anime 中的标题确实是候选词的前缀，避免把续作错配到第一季）

归一化由 `AnimeTitleMatcher` 负责，需注意两个易错点：
- 标题可能使用**全角空格**（U+3000），默认模式下 `\s` 不匹配它
- 季数可能是**全角数字**（`Season２`），`\d` 不匹配全角数字，需用 `[0-9０-９]`

**实测效果**（2026 秋季番首批 50 条）：精确匹配命中 1 条，加入归一化与前缀匹配后命中 6 条；
其余为 `anime` 表中确实不存在的新作（该表仅 1517 条已完结作品），会进入 MAL ID 补抓队列。

### 速率限制

**Jikan API 限制**:
- 每秒最多 3 次请求
- 每分钟最多 60 次请求
- 超出限制返回 429 Too Many Requests

**应对策略**:
1. 每次请求后休眠 1 秒
2. 捕获 429 错误，等待后重试
3. 批量抓取时使用指数退避算法

```java
// 重试逻辑示例
int maxRetries = 3;
for (int i = 0; i < maxRetries; i++) {
    try {
        return restTemplate.getForObject(url, JsonResponse.class);
    } catch (HttpClientErrorException.TooManyRequests e) {
        Thread.sleep((i + 1) * 2000); // 递增等待时间
    }
}
throw new RuntimeException("超过最大重试次数");
```

## 🔄 数据解析与映射

### 1. Broadcast 字段解析

Jikan API 的 `broadcast.day` 字段可能为：
- `"Mondays"` - 星期一（复数形式）
- `"Tuesday"` - 星期二（单数形式）
- `null` - 待定

**解析逻辑**:
```java
private Integer parseBroadcastDay(String day) {
    if (day == null || day.isEmpty()) {
        return 8; // 待定
    }
    
    // 去除复数后缀 's'
    String normalized = day.toLowerCase().replaceAll("s$", "");
    
    switch (normalized) {
        case "monday": return 1;
        case "tuesday": return 2;
        case "wednesday": return 3;
        case "thursday": return 4;
        case "friday": return 5;
        case "saturday": return 6;
        case "sunday": return 7;
        default: return 8; // 未知情况也视为待定
    }
}
```

### 定时任务实现

```java
@Component
@Slf4j
@RequiredArgsConstructor
public class SeasonalAnimeScheduler {
    
    private final SeasonalScraperService seasonalScraperService;
    
    /**
     * 每天凌晨 00:00 执行智能更新
     */
    @Scheduled(cron = "0 0 0 * * ?")
    public void smartUpdateSeasonalAnime() {
        log.info("开始执行当季新番智能更新定时任务");
        
        try {
            Integer count = seasonalScraperService.smartUpdateSeasonalAnime();
            log.info("当季新番智能更新完成: 保存 {} 条记录", count);
        } catch (Exception e) {
            log.error("当季新番智能更新失败: {}", e.getMessage(), e);
        }
    }
}
```

**Cron 表达式说明**:
- `0 0 0 * * ?` - 每天凌晨 00:00
- 秒 分 时 日 月 周

**注意事项**:
- 定时任务默认单线程执行
- 长时间运行的任务应配置线程池
- 异常必须捕获，避免影响后续任务

- 数据更新后立即清除相关缓存
- 使用通配符删除模式匹配的缓存
- 避免脏数据影响用户体验

## 📝 常见问题

### Q1: 如何处理 API 速率限制？

**A**: 
- 每次请求后休眠 1 秒
- 捕获 429 错误，指数退避重试
- 批量操作时使用队列异步处理

### Q2: 为什么 broadcast.day 有时是复数形式？

**A**: Jikan API 的设计问题，需要统一处理。通过去除末尾的 's' 并转换为小写来标准化。

### Q3: 如何避免重复抓取相同数据？

**A**: 
- 使用唯一索引约束（main_id）
- 插入时使用 `ON DUPLICATE KEY UPDATE`
- 应用层检查是否存在

### Q4: 定时任务执行失败怎么办？

**A**: 
- 记录详细错误日志
- 手动触发重新执行
- 可扩展为失败重试机制

### Q5: 如何处理动漫标题的多语言问题？

**A**: 
- 同时存储 title, title_english, title_japanese
- 搜索时匹配所有语言字段
- 显示时优先显示中文标题（从映射表获取）
