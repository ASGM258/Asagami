# 角色管理功能文档

## 📋 功能概述

本模块提供完整的角色数据管理功能，包括角色列表查询、角色详情展示、角色收藏等功能。支持按角色名称模糊搜索、分页查询，并集成 Redis 缓存提升性能。每个角色详情页包含评论系统和点赞功能。

## 🔧 技术实现

### 核心技术栈
- **MyBatis** - ORM 框架
- **PageHelper** - 分页插件
- **Redis** - 数据缓存
- **Jackson JSR310** - Java 8 日期时间序列化

### 架构设计
```
客户端 → CharacterController → CharacterQueryService → CharacterMapper → Database
                                    ↓                          ↓
                              CacheService              NameMapping
                                    ↓
                                  Redis
```

## 📡 API 接口详情

### 1. 分页查询角色列表

**接口地址**: `GET /api/character/list`

**请求参数**:
```
pageNum: 1              // 页码，默认1
pageSize: 10            // 每页数量，默认10
name: "艾伦"            // 角色名称（可选，支持模糊匹配）
```

**响应示例**:
```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "total": 50,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 5,
    "list": [
      {
        "id": 1,
        "malId": 40882,
        "name": "Eren Yeager",
        "nameJapanese": "エレン・イェーガー",
        "imageUrl": "https://cdn.myanimelist.net/images/characters/10/216895.jpg",
        "about": "年龄：15岁...",
        "animeTitle": "Shingeki no Kyojin",
        "animeMainId": 16498,
        "isFavorite": false
      }
    ]
  }
}
```

**业务逻辑**:
1. 获取当前用户 ID（可能为 null）
2. 生成缓存键（包含用户维度）
3. 尝试从 Redis 获取缓存
4. 缓存未命中时查询数据库
5. 联表查询角色所属动漫信息
6. 联表查询用户喜欢状态
7. 设置缓存并返回结果

**缓存策略**:
- 缓存键格式：`character:page:{pageNum}:{pageSize}:{name}:{userId}`
- 过期时间：30 分钟
- 清除时机：更新喜欢状态后清除相关分页缓存

### 3. 更新喜欢角色状态

**接口地址**: `POST /api/character/favorite/update`

**请求头**:
```
Authorization: Bearer <token>
```

**请求参数**:
```json
{
  "characterId": 1,           // 角色ID，必填
  "favoriteStatus": 1         // 喜欢状态：1-喜欢，0-取消喜欢
}
```

**响应示例**:
```json
{
  "code": 200,
  "message": "喜欢成功",
  "data": true
}
```

**业务逻辑**:
1. 验证用户登录状态
2. 验证角色 ID 是否存在
3. 验证喜欢状态合法性（0 或 1）
4. 检查是否已存在记录
   - 存在：UPDATE 更新状态
   - 不存在：INSERT 新增记录
5. 清除相关缓存
   - 角色详情缓存
   - 角色列表分页缓存

**错误码**:
- `401` - 未登录
- `400` - 参数错误
- `404` - 角色不存在

## 🗄️ 数据库设计

### character 表（角色主表）

```sql
CREATE TABLE `character` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '角色ID',
  `mal_id` INT DEFAULT NULL COMMENT 'MAL角色ID',
  `name` VARCHAR(500) NOT NULL COMMENT '角色名称（英文）',
  `name_japanese` VARCHAR(500) DEFAULT NULL COMMENT '角色名称（日文）',
  `image_url` VARCHAR(1000) DEFAULT NULL COMMENT '角色图片URL',
  `about` TEXT COMMENT '角色介绍',
  `anime_title` VARCHAR(500) DEFAULT NULL COMMENT '所属动漫标题',
  `anime_main_id` INT DEFAULT NULL COMMENT '所属动漫MAL ID',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_mal_id` (`mal_id`),
  KEY `idx_name` (`name`(100)),
  KEY `idx_name_japanese` (`name_japanese`(100)),
  KEY `idx_anime_main_id` (`anime_main_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色表';
```

**索引说明**:
- `PRIMARY KEY (id)` - 主键索引
- `UNIQUE KEY uk_mal_id` - MAL ID 唯一索引
- `KEY idx_name` - 角色名称前缀索引（支持模糊搜索）
- `KEY idx_name_japanese` - 日文名称前缀索引
- `KEY idx_anime_main_id` - 所属动漫索引

---

### user_favorite_character 表（用户喜欢角色表）

```sql
CREATE TABLE `user_favorite_character` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `character_id` BIGINT NOT NULL COMMENT '角色ID',
  `favorite_status` TINYINT NOT NULL DEFAULT 1 COMMENT '喜欢状态：1-喜欢，0-取消',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_character` (`user_id`, `character_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_character_id` (`character_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户喜欢角色表';
```

**唯一索引**:
- `uk_user_character` - 防止重复喜欢记录

**字段说明**:
- `favorite_status` - 使用 TINYINT 类型，1 表示喜欢，0 表示取消喜欢
- 不直接删除记录，而是更新状态，保留历史记录

## 🔍 查询优化

### 1. 联表查询角色列表

使用 MyBatis XML 动态 SQL 进行联表查询：

```xml
<select id="selectCharacterPage" resultMap="CharacterSimpleDTOResultMap">
  SELECT 
    c.id,
    c.mal_id,
    c.name,
    c.name_japanese,
    c.image_url,
    c.about,
    c.anime_title,
    c.anime_main_id,
    ufc.favorite_status
  FROM character c
  LEFT JOIN user_favorite_character ufc 
    ON c.id = ufc.character_id AND ufc.user_id = #{userId}
  <where>
    <if test="name != null and name != ''">
      AND (c.name LIKE CONCAT('%', #{name}, '%') 
           OR c.name_japanese LIKE CONCAT('%', #{name}, '%'))
    </if>
  </where>
  ORDER BY c.create_time DESC
</select>
```

**优势**:
- 一次查询获取角色信息和喜欢状态
- 避免 N+1 查询问题
- 支持中英文/日文名称模糊匹配

### 3. 缓存优化

#### 缓存键设计规范

```java
// 列表分页缓存（包含用户维度）
String cacheKey = String.format("character:page:%d:%d:%s:%d", 
    pageNum, pageSize, nameKey, userId != null ? userId : 0);

// 详情缓存（包含用户维度）
String cacheKey = String.format("character:detail:%d:%d", 
    characterId, userId != null ? userId : 0);
```

**设计原则**:
- 包含所有影响结果的参数
- 区分不同用户的缓存
- 使用统一的缓存前缀

#### 缓存清除策略

```java
// 更新喜欢状态后清除相关缓存
public void clearCharacterCache(Long characterId, Long userId) {
    // 清除角色详情缓存（所有用户）
    cacheService.deleteByPattern("character:detail:" + characterId + ":*");
    
    // 清除列表分页缓存（该用户的所有分页）
    cacheService.deleteByPattern("character:page:*:*:*:" + userId);
}
```

## ⚠️ 注意事项

### 性能优化

1. **避免大字段查询**
   - 列表查询不包含 about 等大字段
   - 详情页才加载完整介绍

2. **合理使用索引**
   - 名称字段使用前缀索引（100字符）
   - 所属动漫建立普通索引
   - 用户喜欢表建立联合唯一索引

3. **缓存粒度控制**
   - 列表缓存按用户维度隔离
   - 详情缓存包含用户状态
   - 设置合理的过期时间

### 数据一致性

1. **缓存与数据库同步**
   - 数据更新后立即清除相关缓存
   - 使用通配符删除模式缓存
   - 避免脏数据

2. **并发控制**
   - 喜欢记录使用唯一索引防止重复
   - 数据库层面保证数据完整性
   - 应用层处理冲突

### 扩展性

1. **搜索功能增强**
   - 当前使用 LIKE 模糊匹配
   - 可集成 Elasticsearch 实现全文搜索
   - 支持拼音搜索、分词搜索

2. **角色推荐**
   - 基于用户喜欢的角色推荐相似角色
   - 基于同一动漫的角色推荐
   - 热门角色榜单

## 📝 常见问题

### Q1: 如何实现角色名称的多语言搜索？

**A**: 在 WHERE 条件中同时匹配英文名和日文名字段：
```sql
WHERE name LIKE '%keyword%' OR name_japanese LIKE '%keyword%'
```

### Q2: 为什么喜欢状态使用 0/1 而不是直接删除记录？

**A**: 
- 保留历史记录，便于数据分析
- 避免频繁插入删除
- 可以统计用户的历史喜好变化

### Q3: 如何处理角色所属动漫的变化？

**A**: 
- 角色表中存储 anime_main_id（MAL ID）
- 通过 MAL ID 关联到 anime 表
- 爬虫更新时同步更新角色信息

### Q4: 角色详情页的评论如何排序？

**A**: 
- 按创建时间倒序排列（最新的在前）
- 可在前端实现按点赞数排序
- 支持置顶评论功能（需扩展）
