# 评论系统功能文档

## 📋 功能概述

本模块提供完整的评论系统功能，包括动漫评论、角色评论、多级回复、点赞等功能。支持用户发表评论、回复他人评论、点赞/取消点赞、删除评论等操作，并实现权限验证和缓存优化。

## 🔧 技术实现

### 核心技术栈
- **MyBatis** - ORM 框架
- **Redis** - 点赞状态缓存
- **Spring Validation** - 参数校验
- **UserContext** - 用户身份获取

### 架构设计
```
客户端 → CommentController → CommentService → CommentMapper → Database
                                    ↓
                              UserCommentLike (点赞记录)
                                    ↓
                                  Redis Cache
```

## 📡 API 接口详情

### 动漫评论模块 `/api/comment`

#### 1. 发表评论

**接口地址**: `POST /api/comment/add`

**请求头**:
```
Authorization: Bearer <token>
```

**请求参数**:
```json
{
  "animeId": 1,              // 动漫ID，必填
  "content": "神作！"         // 评论内容，必填，不能为空
}
```

**响应示例**:
```json
{
  "code": 200,
  "message": "评论发表成功",
  "data": {
    "commentId": 1,
    "userId": 1,
    "username": "testuser",
    "avatar": "https://oss.example.com/avatars/xxx.jpg",
    "content": "神作！",
    "likeCount": 0,
    "createTime": "2026-07-09T15:30:00",
    "isLiked": false,
    "replies": []
  }
}
```

**业务逻辑**:
1. 验证用户登录状态
2. 验证动漫 ID 是否存在
3. 验证评论内容不为空
4. 插入评论记录
5. 查询评论人信息（用户名、头像）
6. 返回完整评论信息

**错误码**:
- `401` - 未登录
- `400` - 参数错误
- `404` - 动漫不存在

**接口地址**: `POST /api/comment/reply/add`

**请求头**:
```
Authorization: Bearer <token>
```

**请求参数**:
```json
{
  "commentId": 1,           // 主评论ID，必填
  "parentReplyId": null,    // 父回复ID（可选，回复评论时为null）

```

**响应示例**:
```json
{
  "code": 200,
  "message": "回复发表成功",
  "data": {
    "replyId": 1,
    "userId": 2,
    "username": "user2",
    "avatar": "https://oss.example.com/avatars/yyy.jpg",

  }

```

**业务逻辑**:
1. 验证用户登录状态
2. 验证主评论是否存在

5. 查询回复人信息

- 一级回复：直接回复评论（parentReplyId = null）
- 二级回复：回复其他回复（parentReplyId != null）
- 不支持更深层级的嵌套

**错误码**:
- `401` - 未登录
- `400` - 参数错误
- `404` - 评论或回复不存在

#### 7. 点赞/取消点赞

**接口地址**: `POST /api/comment/like`

**请求头**:
```
Authorization: Bearer <token>
```

**请求参数**:
```json
{
  "commentId": 1,          // 评论ID（点赞评论时必填）
  "replyId": null,         // 回复ID（点赞回复时必填）
  "type": "like",          // 操作类型：like-点赞，unlike-取消点赞
  "targetType": "comment"  // 目标类型：comment-评论，reply-回复
}
```

**响应示例**:
```json
{
  "code": 200,
  "message": "点赞成功",
  "data": true
}
```

**业务逻辑**:
1. 验证用户登录状态
2. 验证参数合法性（commentId/replyId 二选一）
3. 验证 type 和 targetType 合法性
4. 检查是否已存在点赞记录
   - type="like" 且不存在：INSERT 新增
   - type="like" 且已存在：忽略
   - type="unlike" 且存在：DELETE 删除
   - type="unlike" 且不存在：忽略
5. 更新点赞计数
6. 清除相关缓存

**点赞规则**:
- 一个用户对一条评论/回复只能点赞一次
- 重复点赞不重复插入记录
- 取消点赞时删除记录

**错误码**:
- `401` - 未登录
- `400` - 参数错误

### user_comment_like 表（用户评论点赞表）

```sql
CREATE TABLE `user_comment_like` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `target_id` BIGINT NOT NULL COMMENT '目标ID（评论ID或回复ID）',
  `target_type` VARCHAR(20) NOT NULL COMMENT '目标类型：comment-评论，reply-回复',
  `level` TINYINT DEFAULT NULL COMMENT '层级：1-一级评论，2-二级回复',
  `anime_id` BIGINT DEFAULT NULL COMMENT '动漫ID（冗余字段，便于查询）',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_target` (`user_id`, `target_id`, `target_type`),
  KEY `idx_anime_id` (`anime_id`),
  KEY `idx_target` (`target_id`, `target_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户评论点赞表';
```

**唯一索引**:
- `uk_user_target` - 防止重复点赞（用户+目标ID+目标类型）

**字段说明**:
- `target_id` - 通用目标ID，可以是评论ID或回复ID
- `target_type` - 区分目标是评论还是回复
- `level` - 冗余字段，便于统计
- `anime_id` - 冗余字段，便于查询某动漫下的点赞记录

**设计优势**:
- 统一存储评论和回复的点赞记录
- 通过唯一索引防止重复点赞
- 冗余字段提升查询性能

## 🔍 查询优化

### 1. 批量查询点赞状态

```java
// 收集所有需要查询的评论ID和回复ID
List<Long> commentIds = comments.stream()
    .map(CommentResponse::getCommentId)
    .collect(Collectors.toList());

List<Long> replyIds = comments.stream()
    .flatMap(comment -> comment.getReplies().stream())
    .map(CommentReplyResponse::getReplyId)
    .collect(Collectors.toList());

// 批量查询用户点赞的评论ID
Set<Long> likedCommentIds = new HashSet<>();
if (!commentIds.isEmpty()) {
    likedCommentIds = userCommentLikeMapper
        .selectLikedTargetIds(userId, commentIds, "comment");
}

// 批量查询用户点赞的回复ID
Set<Long> likedReplyIds = new HashSet<>();
if (!replyIds.isEmpty()) {
    likedReplyIds = userCommentLikeMapper
        .selectLikedTargetIds(userId, replyIds, "reply");
}
```

**优势**:
- 减少数据库查询次数
- 从 N+1 次查询优化到 2 次查询
- 显著提升响应速度

---

### 2. 联表查询评论人信息

```xml
<select id="selectCommentsByAnimeId" resultMap="CommentResponseResultMap">
  SELECT 
    c.id as comment_id,
    c.anime_id,
    c.user_id,
    c.content,
    c.like_count,
    c.create_time,
    u.username,
    u.avatar
  FROM anime_comment c
  LEFT JOIN user u ON c.user_id = u.id
  WHERE c.anime_id = #{animeId}
  ORDER BY c.create_time DESC
</select>
```

**优势**:
- 一次查询获取评论和用户信息
- 避免循环查询用户表

---

### 3. 点赞计数更新

```java
// 点赞时增加计数
@Update("UPDATE anime_comment SET like_count = like_count + 1 WHERE id = #{commentId}")
void incrementLikeCount(Long commentId);

// 取消点赞时减少计数
@Update("UPDATE anime_comment SET like_count = GREATEST(like_count - 1, 0) WHERE id = #{commentId}")
void decrementLikeCount(Long commentId);
```

**注意事项**:
- 使用 `GREATEST` 函数防止计数变为负数
- 点赞计数与点赞记录表保持一致性

## ⚠️ 注意事项

### 权限控制

1. **评论/回复删除权限**
   - 只有作者可以删除自己的评论/回复
   - 删除前必须验证用户身份
   - 管理员可扩展删除权限

2. **点赞防重复**
   - 使用唯一索引防止重复点赞
   - 应用层检查 + 数据库约束双重保障

### 性能优化

1. **避免 N+1 查询**
   - 批量查询点赞状态
   - 联表查询用户信息
   - 使用 IN 查询代替循环查询

2. **缓存策略**

## 📝 常见问题

### Q1: 如何实现评论的分页查询？

**A**: 
- 当前实现返回全部评论
- 可使用 PageHelper 实现分页
- 建议按时间或点赞数排序

### Q2: 点赞计数与实际点赞记录不一致怎么办？

**A**: 
- 定期执行数据一致性校验任务
- 根据点赞记录表重新计算计数
- 使用事务保证原子性

### Q3: 如何防止刷赞行为？

**A**: 
- 限制单位时间内的点赞次数
- 使用 Redis 记录点赞频率
- 异常行为触发风控

### Q4: 评论支持富文本吗？

**A**: 
- 当前仅支持纯文本
- 可扩展支持 Markdown
- 需要前端渲染引擎
