# 用户认证与授权功能文档

## 📋 功能概述

本模块提供完整的用户认证与授权功能，包括用户注册、登录、个人信息管理等功能。采用 JWT（JSON Web Token）单 Token 机制实现安全的身份验证，使用 BCrypt 加密存储用户密码。

## 🔧 技术实现

### 核心技术栈
- **Spring Security** - 安全框架基础
- **JJWT 0.11.5** - JWT Token 生成与验证
- **BCrypt** - 密码加密算法
- **Jakarta Validation** - 参数校验

### 架构设计
```
客户端 → AuthController → AuthService → UserMapper → Database
                    ↓
              JwtTokenProvider (生成/验证Token)
                    ↓
              PasswordEncoder (密码加密)
```

## 📡 API 接口详情

### 1. 用户注册

**接口地址**: `POST /api/auth/register`

**请求参数**:
```json
{
  "username": "string",    // 用户名，必填，3-20个字符
  "email": "string",       // 邮箱，必填，需符合邮箱格式
  "password": "string"     // 密码，必填，最少6个字符
}
```

**响应示例**:
```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "userId": 1,
    "username": "testuser",
    "email": "test@example.com",
    "avatar": null,
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "tokenType": "Bearer"
  }
}
```

**业务逻辑**:
1. 校验用户名是否已存在
2. 校验邮箱是否已注册
3. 使用 BCrypt 加密密码
4. 创建用户记录
5. 生成 JWT Token
6. 返回用户信息和 Token

**错误码**:
- `400` - 用户名或邮箱已存在
- `400` - 参数格式错误

**请求参数**:

**业务逻辑**:

## 🔐 JWT 认证机制

### Token 结构

JWT Token 包含三部分：
1. **Header** - 加密算法和 Token 类型
2. **Payload** - 用户信息（userId, username, expiration）
3. **Signature** - 签名验证

### Token 配置

在 `application.yaml` 中配置：
```yaml
jwt:
  secret: ${JWT_SECRET:your_secret_key}
  expiration: ${JWT_EXPIRATION:18000000}  # 默认5小时（毫秒）
```

### Token 生命周期

1. **生成**: 用户登录成功后生成 Token
2. **传递**: 客户端在请求头中携带 `Authorization: Bearer <token>`
3. **验证**: `JwtAuthenticationInterceptor` 拦截器验证 Token
4. **过期**: Token 超过有效期后自动失效

### 拦截器实现

**JwtAuthenticationInterceptor** 负责：
- 从请求头提取 Token
- 验证 Token 有效性
- 解析用户 ID 并注入到请求属性
- 将用户信息存入 `UserContext`

## 👤 用户上下文管理

### UserContext

`UserContext` 使用 `ThreadLocal` 存储当前请求的用户信息：

```java
public class UserContext {
    private static final ThreadLocal<Long> userIdHolder = new ThreadLocal<>();
    
    public static void setUserId(Long userId) {
        userIdHolder.set(userId);
    }
    
    public static Long getUserId() {
        return userIdHolder.get();
    }
    
    public static void clear() {
        userIdHolder.remove();
    }
}
```

**使用场景**:
- Service 层获取当前登录用户 ID
- 记录操作日志
- 权限验证

## 🔒 安全特性

### 1. 密码加密

使用 **BCrypt** 算法加密用户密码：
- 自动加盐（Salt）
- 不可逆加密
- 抗暴力破解

```java
// 加密
String encodedPassword = passwordEncoder.encode(rawPassword);

// 验证
boolean matches = passwordEncoder.matches(rawPassword, encodedPassword);
```

### 2. 参数校验

使用 Jakarta Validation 进行输入验证：

```java
public class RegisterRequest {
    @NotBlank(message = "用户名不能为空")
    @Size(min = 3, max = 20, message = "用户名长度必须在3-20之间")
    private String username;
    
    @Email(message = "邮箱格式不正确")
    private String email;
    
    @NotBlank(message = "密码不能为空")
    @Size(min = 6, message = "密码长度至少6位")
    private String password;
}
```

### 3. CORS 配置

在 `WebMvcConfig` 中配置跨域访问：

```java
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/**")
            .allowedOriginPatterns("*")
            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
            .allowedHeaders("*")
            .allowCredentials(true)
            .maxAge(3600);
}
```

### 4. 异常处理

`GlobalExceptionHandler` 统一处理认证相关异常：
- `AuthenticationException` - 认证失败
- `AccessDeniedException` - 权限不足
- `MethodArgumentNotValidException` - 参数校验失败

## 📊 数据库设计

### user 表结构

```sql
CREATE TABLE `user` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `username` VARCHAR(50) NOT NULL COMMENT '用户名',
  `email` VARCHAR(100) NOT NULL COMMENT '邮箱',
  `password` VARCHAR(255) NOT NULL COMMENT '密码（BCrypt加密）',
  `avatar` VARCHAR(500) DEFAULT NULL COMMENT '头像URL',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`),
  UNIQUE KEY `uk_email` (`email`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**索引说明**:
- `PRIMARY KEY (id)` - 主键索引
- `UNIQUE KEY uk_username` - 用户名唯一索引
- `UNIQUE KEY uk_email` - 邮箱唯一索引

## ⚠️ 注意事项

### 安全性

1. **JWT Secret 保护**
   - 生产环境必须使用环境变量配置
   - 不要将 Secret 提交到版本控制系统
   - 定期更换 Secret

2. **Token 过期时间**
   - 根据业务需求设置合理的过期时间
   - 建议不超过 24 小时
   - 敏感操作可要求重新登录

3. **密码策略**
   - 强制最小长度（至少 6 位）
   - 建议增加复杂度要求（大小写、数字、特殊字符）
   - 防止常见弱密码

### 性能优化

1. **Token 验证缓存**
   - 可考虑缓存已验证的 Token
   - 减少重复的签名验证

2. **用户信息查询**
   - 高频访问的用户信息可缓存到 Redis
   - 设置合理的缓存过期时间

### 扩展性

1. **刷新 Token**
   - 当前为单 Token 机制
   - 可扩展为 Access Token + Refresh Token 双 Token 机制

2. **OAuth 集成**
   - 预留第三方登录接口
   - 支持微信、QQ、GitHub 等 OAuth 登录

3. **多设备登录**
   - 记录 Token 与设备的绑定关系
   - 支持踢出其他设备

## 📝 常见问题

### Q1: Token 过期后如何处理？

**A**: 客户端捕获 401 错误，跳转到登录页面重新登录。也可实现 Refresh Token 机制自动续期。

### Q2: 如何强制用户下线？

**A**: 
- 方案1: 维护 Token 黑名单（Redis）
- 方案2: 修改用户密码使旧 Token 失效
- 方案3: 在数据库中记录用户状态，拦截器检查

### Q3: 如何防止 Token 被盗用？

**A**:
- 使用 HTTPS 传输
- Token 绑定 IP 或设备指纹
- 设置较短的过期时间
- 实施速率限制

### Q4: 忘记密码功能如何实现？

**A**: 
1. 用户输入邮箱
2. 发送重置链接（含临时 Token）
3. 用户点击链接设置新密码
4. Token 验证通过后更新密码
