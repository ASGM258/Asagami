# 轮播图功能文档

## 📋 功能概述

本模块提供动漫轮播图展示功能，从数据库中随机选取热门动漫生成轮播图数据。支持自定义数量限制，集成 Redis 缓存提升性能，用于网站首页或动漫列表页的推荐展示。

## 🔧 技术实现

### 核心技术栈
- **MyBatis** - 数据库查询
- **Redis** - 轮播图数据缓存
- **Random** - 随机选取算法
- **CacheService** - 缓存管理

### 架构设计
```
客户端 → BannerController → BannerService → AnimeMapper → Database
                                    ↓
                              CacheService
                                    ↓
                                  Redis
```

## 📡 API 接口详情

### 获取随机轮播图

**接口地址**: `GET /api/anime/banners`

**请求参数**:
```
limit: 10                  // 数量限制（可选，默认10条，最大50条）
```

**响应示例**:
```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": 1,
      "mainId": 16498,
      "title": "Shingeki no Kyojin",
      "chineseTitle": "进击的巨人",
      "coverImage": "https://cdn.myanimelist.net/images/anime/10/47347.jpg",
      "score": 8.54,
      "members": 3200000
    },
    {
      "id": 2,
      "mainId": 5114,
      "title": "Fullmetal Alchemist: Brotherhood",
      "chineseTitle": "钢之炼金术师 FA",
      "coverImage": "https://cdn.myanimelist.net/images/anime/1223/96541.jpg",
      "score": 9.16,
      "members": 2800000
    }
  ]
}
```

**业务逻辑**:
1. 验证 limit 参数（默认 10，最大 50）
2. 生成缓存键
3. 尝试从 Redis 获取缓存
4. 缓存未命中时查询数据库
   - 按收藏人数（members）降序排列
   - 随机选取指定数量的动漫
5. 组装轮播图数据
6. 设置缓存并返回结果

**缓存策略**:
- 缓存键格式：`anime:banners:{limit}`
- 过期时间：1 小时
- 清除时机：爬虫更新动漫数据后清除所有轮播图缓存

**错误码**:
- `400` - limit 参数超出范围

## 🗄️ 数据库查询

### SQL 查询逻辑

```xml
<select id="selectRandomBanners" resultType="com.anime.manager.dto.BannerItem">
  SELECT 
    a.id,
    a.main_id,
    a.title,
    nm.chinese_title,
    a.cover_image,
    a.score,
    a.members
  FROM anime a
  LEFT JOIN anime_name_mapping nm ON a.id = nm.anime_id
  WHERE a.cover_image IS NOT NULL
    AND a.members > 0
  ORDER BY a.members DESC
  LIMIT #{limit}
</select>
```

**查询条件**:
- `cover_image IS NOT NULL` - 必须有封面图
- `members > 0` - 必须有收藏人数
- `ORDER BY members DESC` - 按热门程度排序

**随机策略**:
- 当前实现：取前 N 个热门动漫（确定性）
- 可扩展：使用 `ORDER BY RAND()` 真正随机
- 权衡：确定性利于缓存，随机性提升新鲜感

## 💾 缓存策略

### 缓存键设计

```java
String cacheKey = String.format("anime:banners:%d", limit);
```

**示例**:
```
anime:banners:10    // 10条轮播图
anime:banners:20    // 20条轮播图
anime:banners:5     // 5条轮播图
```

### 缓存清除

```java
// 爬虫更新数据后清除所有轮播图缓存
public void clearBannerCache() {
    cacheService.deleteByPattern("anime:banners:*");
}
```

**清除时机**:
- 爬虫抓取新动漫后
- 批量更新动漫数据后
- 手动刷新缓存时

## ⚠️ 注意事项

### 性能优化

1. **限制最大数量**
   - 防止用户请求过多数据
   - 建议最大值 50
   - 减少数据库压力

2. **缓存热点数据**
   - 轮播图访问频率高
   - 缓存时间可较长（1小时）
   - 不同 limit 分别缓存

3. **索引优化**
   - `members` 字段建立索引
   - `cover_image` 字段建立索引
   - 加速 WHERE 条件查询

## 📝 常见问题

### Q1: 如何实现真正的随机轮播图？

**A**: 
- 使用 `ORDER BY RAND()` SQL 函数
- 但性能较差，不适合大数据量
- 可在应用层随机选取

### Q2: 轮播图数据不更新怎么办？

**A**: 
- 检查缓存是否过期
- 手动清除缓存
- 验证爬虫是否正常更新数据

### Q3: 如何控制轮播图的展示内容？

**A**: 
- 添加筛选条件（类型、季度等）
- 后台配置推荐列表
- 算法智能推荐

### Q4: 轮播图点击统计如何实现？

**A**: 
- 前端上报点击事件
- 后端记录点击日志
- 统计分析展示效果
