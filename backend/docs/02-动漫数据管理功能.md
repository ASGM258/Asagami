# 动漫数据管理功能文档

## 📋 功能概述

本模块提供完整的动漫数据管理功能，包括动漫列表查询、详情展示、追番记录、观看历史等功能。支持按标题模糊搜索、按年份筛选、中文标题映射等特性，并集成 Redis 缓存提升查询性能。

## 🔧 技术实现

### 核心技术栈
- **MyBatis** - ORM 框架，支持动态 SQL
- **PageHelper** - 分页插件
- **Redis** - 数据缓存
- **Jackson JSR310** - Java 8 日期时间序列化支持

### 架构设计
```
客户端 → AnimeController → AnimeQueryService → AnimeMapper → Database
                                    ↓                    ↓
                              CacheService          NameMapping
                                    ↓
                                  Redis
```

## 📡 API 接口详情

### 1. 分页查询动漫列表

**接口地址**: `GET /api/anime/list`

**请求参数**:
```
pageNum: 1              // 页码，默认1
pageSize: 10            // 每页数量，默认10
title: "进击的巨人"      // 标题搜索关键词（可选）
year: 2013              // 年份过滤（可选）
```

**响应示例**:
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 100,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 10,
    "list": [
      {
        "id": 1,
        "mainId": 16498,
        "title": "Shingeki no Kyojin",
        "chineseTitle": "进击的巨人",
        "coverImage": "https://cdn.myanimelist.net/images/anime/10/47347.jpg",
        "synopsis": "故事发生在...",
        "score": 8.54,
        "members": 3200000,
        "status": "Finished Airing",
        "episodes": 25,
        "airedFrom": "2013-04-07",
        "watchStatus": null,
        "isFavorite": false
      }
    ]
  }
}
```

**业务逻辑**:
1. 获取当前用户 ID（可能为 null）
2. 生成缓存键（包含用户维度）
3. 尝试从 Redis 获取缓存
4. 缓存未命中时查询数据库
5. 联表查询中文标题和封面图
6. 联表查询用户追番状态
7. 设置缓存并返回结果

**缓存策略**:
- 缓存键格式：`anime:page:{pageNum}:{pageSize}:{title}:{year}:{userId}`
- 过期时间：30 分钟
- 清除时机：爬虫更新数据后清除相关分页缓存

### 3. 更新追番状态

**接口地址**: `PUT /api/anime/user/update`

**请求头**:
```
Authorization: Bearer <token>
```

**请求参数**:
```json
{
  "animeId": 1,                    // 动漫ID，必填
  "watchStatus": "WATCHING",       // 观看状态，必填
  "currentEpisode": 10,            // 当前观看集数，可选
  "score": 9                       // 评分（1-10），可选
}
```

**观看状态枚举**:
- `PLAN_TO_WATCH` - 想看
- `WATCHING` - 在看
- `COMPLETED` - 看完
- `ON_HOLD` - 搁置
- `DROPPED` - 弃番

**响应示例**:
```json
{
  "code": 200,
  "message": "更新成功",
  "data": true
}
```

**业务逻辑**:
1. 验证用户登录状态
2. 验证动漫 ID 是否存在
3. 验证观看状态合法性
4. 检查是否已存在记录
   - 存在：UPDATE 更新
   - 不存在：INSERT 新增
5. 清除相关缓存
   - 动漫详情缓存
   - 用户追番列表缓存

**错误码**:
- `401` - 未登录
- `400` - 参数错误
- `404` - 动漫不存在

## 🔍 查询优化

### 1. 联表查询

使用 MyBatis XML 动态 SQL 进行联表查询：

```xml
<select id="selectAnimePage" resultMap="AnimeSimpleDTOResultMap">
  SELECT 
    a.id,
    a.main_id,
    a.title,
    a.cover_image,
    a.synopsis,
    a.score,
    a.members,
    a.status,
    a.episodes,
    a.aired_from,
    nm.chinese_title,
    ua.watch_status,
    ua.current_episode,
    ua.score as user_score
  FROM anime a
  LEFT JOIN anime_name_mapping nm ON a.id = nm.anime_id
  LEFT JOIN user_anime ua ON a.id = ua.anime_id AND ua.user_id = #{userId}
  <where>
    <if test="title != null and title != ''">
      AND (a.title LIKE CONCAT('%', #{title}, '%') 
           OR a.title_english LIKE CONCAT('%', #{title}, '%')
           OR a.title_japanese LIKE CONCAT('%', #{title}, '%')
           OR nm.chinese_title LIKE CONCAT('%', #{title}, '%'))
    </if>
    <if test="year != null">
      AND a.year = #{year}
    </if>
  </where>
  ORDER BY a.members DESC
</select>
```

**优势**:
- 一次查询获取所有需要的数据
- 避免 N+1 查询问题
- 支持多字段模糊匹配

### 3. 缓存优化

#### 缓存键设计规范

```java
// 列表分页缓存（包含用户维度）
String cacheKey = String.format("anime:page:%d:%d:%s:%d:%d", 
    pageNum, pageSize, titleKey, year != null ? year : 0, 
    userId != null ? userId : 0);

// 详情缓存（包含用户维度）
String cacheKey = String.format("anime:detail:%d:%d", 
    animeId, userId != null ? userId : 0);

// 追番历史缓存
String cacheKey = String.format("anime:user:history:%d:%s:%d:%d", 
    userId, statusKey, pageNum, pageSize);
```

**设计原则**:
- 包含所有影响结果的参数
- 区分不同用户的缓存
- 使用统一的缓存前缀

#### 缓存清除策略

```java
// 更新追番状态后清除相关缓存
public void clearAnimeCache(Long animeId, Long userId) {
    // 清除动漫详情缓存（所有用户）
    cacheService.deleteByPattern("anime:detail:" + animeId + ":*");
    
    // 清除该用户的追番历史缓存
    cacheService.deleteByPattern("anime:user:history:" + userId + ":*");
    
    // 清除列表分页缓存（该用户的所有分页）
    cacheService.deleteByPattern("anime:page:*:*:*:*:" + userId);
}
```

## ⚠️ 注意事项

### 性能优化

1. **避免大字段查询**
   - 列表查询不包含 synopsis 等大字段
   - 详情页才加载完整信息

2. **合理使用索引**
   - 标题字段使用前缀索引
   - 年份、季度建立普通索引
   - 用户追番表建立联合唯一索引

3. **缓存粒度控制**
   - 列表缓存按用户维度隔离
   - 详情缓存包含用户状态
   - 设置合理的过期时间

### 数据一致性

1. **缓存与数据库同步**
   - 数据更新后立即清除相关缓存
   - 使用通配符删除模式缓存
   - 避免脏数据

2. **并发控制**
   - 追番记录使用唯一索引防止重复
   - 数据库层面保证数据完整性
   - 应用层处理冲突

### 扩展性

1. **搜索功能增强**
   - 当前使用 LIKE 模糊匹配
   - 可集成 Elasticsearch 实现全文搜索
   - 支持拼音搜索、分词搜索

2. **推荐系统**
   - 基于用户追番记录推荐相似动漫
   - 基于协同过滤算法
   - 热门榜单、新番推荐

## 📝 常见问题

### Q1: 如何实现中文标题搜索？

**A**: 通过 `anime_name_mapping` 表联表查询，在 WHERE 条件中同时匹配英文、日文和中文标题字段。

### Q2: 为什么分页缓存要包含用户维度？

**A**: 因为列表中包含用户的追番状态（watchStatus），不同用户看到的数据不同，需要按用户维度隔离缓存。

### Q3: 如何处理动漫标题的多语言问题？

**A**: 
- 主表存储原始标题（英文/日文）
- 映射表存储中文译名
- 搜索时同时匹配多个语言字段
- 显示时优先显示中文标题

### Q4: 追番状态更新后如何保证缓存一致性？

**A**: 
- 更新成功后立即清除相关缓存
- 使用通配符删除模式匹配的所有缓存键
- 下次查询时重新从数据库加载并缓存
