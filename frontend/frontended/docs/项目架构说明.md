## 🔌 双后端架构

### 架构设计原因

**为什么需要两个后端？**

1. **Java 后端 (Spring Boot)**
   - 优势：企业级框架，适合复杂业务逻辑
   - 职责：用户认证、授权、动漫数据管理、评论系统
   - 端口：8081

2. **Python 后端 (Flask/FastAPI)**
   - 优势：AI/ML 生态丰富，快速原型开发
   - 职责：AI智能问答、会话管理、流式响应
   - 端口：5000

### API 调用策略

**Java 后端 API：**
```typescript
// utils/request.ts
const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:8081/api'
})

// 使用
import { getAnimeList } from '@/api/anime'
const response = await getAnimeList(params)  // → http://localhost:8081/api/anime/list
```

**Python 后端 API：**
```typescript
// api/chat.ts
const PYTHON_API_URL = import.meta.env.VITE_PYTHON_API_URL || 'http://localhost:5000/api'

// 使用 fetch API（因为需要 SSE 流式响应）
const response = await fetch(`${PYTHON_API_URL}/anime-chat-stream`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${token}`
  },
  body: JSON.stringify({ question, user_id, session_id })
})
```

### 响应格式转换

**Python 后端原始格式：**
```json
{
  "success": true,
  "message": "操作成功",
  "data": {...},
  "timestamp": 1234567890
}
```

**转换为前端统一格式：**
```typescript
// api/chat.ts - fetchApi 函数
if (backendData.success) {
  return {
    code: 200,
    message: backendData.message || '操作成功',
    data: backendData.data || null,
    timestamp: backendData.timestamp || Date.now()
  }
} else {
  return {
    code: mapErrorCode(errorInfo.code) || 500,
    message: errorInfo.message || '操作失败',
    data: null,
    timestamp: errorInfo.timestamp || Date.now()
  }
}
```

## 🔄 数据流向

### 典型数据流：获取动漫列表

```
1. 用户访问首页
   ↓
2. HomeView.vue onMounted
   ↓
3. 调用 fetchAnimeList()
   ↓
4. 构建查询参数 { pageNum, pageSize, title?, year? }
   ↓
5. 调用 getAnimeList(params) [api/anime.ts]
   ↓
6. Axios 请求拦截器添加 Authorization Header
   ↓
7. 发送 GET 请求到 http://localhost:8081/api/anime/list
   ↓
8. Java 后端处理请求（PageHelper 分页）
   ↓
9. 返回 PageResponse<Anime>
   ↓
10. Axios 响应拦截器检测 Token 是否过期
    ↓
11. 返回 responseData.data（自动解包）
    ↓
12. HomeView 更新 animeList 和 pagination
    ↓
13. Vue 响应式系统触发 DOM 更新
    ↓
14. 渲染动漫卡片网格
    ↓
15. 图片懒加载触发
```

### 状态管理流程：用户登录

```
1. 用户在 LoginView 输入凭据
   ↓
2. 点击登录按钮
   ↓
3. 调用 authStore.login(loginForm)
   ↓
4. 调用 login API [api/auth.ts]
   ↓
5. POST /auth/login
   ↓
6. Java 后端验证，返回 JWT Token + 用户信息
   ↓
7. Auth Store 更新状态：
   - token.value = accessToken
   - userInfo.value = UserInfo
   - isLoggedIn.value = true
   ↓
8. 持久化到 localStorage：
   - localStorage.setItem('accessToken', token)
   - localStorage.setItem('userInfo', JSON.stringify(userInfo))
   ↓
9. 路由跳转到首页或 redirect 页面
   ↓
10. Layout 组件检测到 isLoggedIn=true，显示用户信息
```

## 🎯 关键设计决策

### 1. 为什么使用 Pinia 而不是 Vuex？

**原因：**
- ✅ Vue 3 官方推荐
- ✅ 更好的 TypeScript 支持
- ✅ 更简洁的 API（无需 mutations）
- ✅ 模块化更清晰
- ✅ 体积更小

**对比：**
```typescript
// Vuex (旧)
export default new Vuex.Store({
  state: { ... },
  mutations: { ... },  // 需要 mutations
  actions: { ... }
})

// Pinia (新)
export const useAuthStore = defineStore('auth', () => {
  const token = ref('')  // 直接定义状态
  const login = async () => { ... }  // 直接定义方法
  return { token, login }
})
```

### 2. 为什么使用 Composition API？

**原因：**
- ✅ 更好的代码组织（按功能而非选项）
- ✅ 更强的 TypeScript 支持
- ✅ 逻辑复用更方便（composables）
- ✅ 更小的打包体积

**示例：**
```vue
<script setup lang="ts">
// 所有相关逻辑放在一起
const { animeList, loading, fetchAnimeList } = useAnimeList()
const { searchQuery, handleSearch } = useSearch()
const { selectedYear, handleYearChange } = useYearFilter()
</script>
```

### 3. 为什么 Token 存储在 localStorage？

**原因：**
- ✅ 刷新页面后保持登录状态
- ✅ 避免 CSRF 攻击（Cookie 容易被 CSRF）
- ✅ 简单易用

**安全考虑：**
- ⚠️ XSS 风险：需要防范 XSS 攻击
- ⚠️ 解决方案：严格转义用户输入，使用 CSP

**替代方案对比：**
| 存储方式 | 优点 | 缺点 |
|---------|------|------|
| localStorage | 持久化、简单 | XSS 风险 |
| sessionStorage | 关闭标签即清除 | 无法跨标签页共享 |
| Cookie | HttpOnly 防 XSS | CSRF 风险、容量小 |

### 4. 为什么使用 Element Plus？

**原因：**
- ✅ 基于 Vue 3，完美兼容
- ✅ 丰富的组件库
- ✅ 完善的文档
- ✅ 活跃的社区
- ✅ TypeScript 支持良好

**替代方案：**
- Ant Design Vue
- Naive UI
- Vuetify

### 5. 为什么使用 Vite？

**原因：**
- ✅ 极速的开发服务器启动
- ✅ 按需编译（ESM）
- ✅ 热模块替换（HMR）更快
- ✅ 内置 TypeScript、SCSS 支持
- ✅ 优秀的生产构建优化

**对比 Webpack：**
- 开发服务器启动：Vite ~1s vs Webpack ~10s
- HMR 更新：Vite 即时 vs Webpack 数秒

## 🔐 安全架构

### 认证流程

```
┌──────────┐         ┌──────────┐         ┌──────────┐
│  前端     │         │ Java后端  │         │ 数据库    │
└────┬─────┘         └────┬─────┘         └────┬─────┘
     │                     │                    │
     │ 1. POST /auth/login │                    │
     │────────────────────>│                    │
     │                     │ 2. 验证用户名密码   │
     │                     │───────────────────>│
     │                     │                    │
     │                     │ 3. 返回用户信息     │
     │                     │<───────────────────│
     │                     │                    │
     │ 4. 生成 JWT Token   │                    │
     │<────────────────────│                    │
     │                     │                    │
     │ 5. 保存 Token       │                    │
     │                     │                    │
     │ 6. 后续请求携带Token│                    │
     │────────────────────>│                    │
     │                     │ 7. 验证 Token      │
     │                     │───────────────────>│
     │                     │                    │
     │ 8. 返回数据         │                    │
     │<────────────────────│                    │
```

### Token 过期处理

**检测机制：**
1. 响应拦截器检查 `code === 1004` 或 `code === 1005`
2. HTTP 状态码 401

**处理流程：**
```typescript
if (responseData.code === 1004 || responseData.code === 1005) {
  // 1. 清除本地存储
  localStorage.removeItem('accessToken')
  localStorage.removeItem('userInfo')
  
  // 2. 跳转登录页
  router.push({
    path: '/login',
    query: { redirect: currentPath }
  })
  
  // 3. 显示提示
  ElMessage.warning('登录已过期，请重新登录')
}
```

## 🚀 部署架构

### 开发环境

```
前端 (localhost:5173) ←→ Java后端 (localhost:8081)
                     ←→ Python后端 (localhost:5000)
```

### 生产环境

**方案一：分离部署**
```
Nginx (静态文件)
  ├─ 前端 dist/
  ├─ 代理 /api → Java后端
  └─ 代理 /ai-api → Python后端
```

**方案二：Docker 容器化**
```dockerfile
# Dockerfile
FROM node:18-alpine AS builder
WORKDIR /app
COPY . .
RUN npm install && npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
```

## 🔄 持续集成/持续部署 (CI/CD)

### GitHub Actions 示例

```yaml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - name: Install dependencies
        run: npm install
      
      - name: Build
        run: npm run build
      
      - name: Deploy to server
        uses: appleboy/scp-action@master
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_KEY }}
          source: dist/*
          target: /var/www/html
```
