# 用户认证系统功能说明

## 📋 功能概述

用户认证系统是整个应用的基础，提供完整的用户注册、登录、身份验证和用户信息管理功能。采用 JWT (JSON Web Token) 进行身份验证，支持 Token 自动刷新和过期处理。

---

## 🎯 核心功能

### 1. 用户注册

**页面路径：** `/register`

**功能描述：**
- 新用户通过用户名、邮箱、密码进行注册
- 可选填写昵称
- 注册成功后自动登录并跳转到首页

**表单字段：**
| 字段 | 类型 | 必填 | 验证规则 |
|------|------|------|----------|
| username | string | ✅ | 3-50个字符 |
| email | string | ✅ | 有效邮箱格式 |
| password | string | ✅ | 6-100个字符 |
| nickname | string | ❌ | 最多50个字符 |

**API 接口：**
```typescript
POST /auth/register
Request: {
  username: string,
  email: string,
  password: string,
  nickname?: string
}
Response: {
  code: 200,
  message: "注册成功",
  data: {
    accessToken: string,
    tokenType: "Bearer",
    userId: number,
    username: string,
    email: string,
    nickname: string,
    avatar: string | null
  }
}
```

**工作流程：**
1. 用户填写注册表单
2. 前端进行表单验证（长度、格式等）
3. 调用 `auth.ts` 中的 `register()` API
4. 后端创建用户并返回 JWT Token
5. 前端保存 Token 和用户信息到 localStorage
6. 显示成功提示，1.5秒后跳转到登录页

**错误处理：**
- 用户名已存在 → 提示"用户名已被使用"
- 邮箱已注册 → 提示"该邮箱已注册"
- 网络错误 → 提示"注册失败，请稍后重试"

---

### 2. 用户登录

**页面路径：** `/login`

**功能描述：**
- 支持用户名或邮箱登录
- 登录成功后跳转到之前访问的页面或首页
- 记住登录状态（Token 持久化）

**表单字段：**
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | string | ✅ | 用户名或邮箱 |
| password | string | ✅ | 密码（至少6位） |

**API 接口：**
```typescript
POST /auth/login
Request: {
  username: string,  // 可以是用户名或邮箱
  password: string
}
Response: {
  code: 200,
  message: "登录成功",
  data: {
    accessToken: string,
    tokenType: "Bearer",
    userId: number,
    username: string,
    email: string,
    nickname: string,
    avatar: string | null
  }
}
```

**工作流程：**
1. 用户输入用户名/邮箱和密码
2. 前端验证（非空、密码长度）
3. 调用 `auth.ts` 中的 `login()` API
4. 后端验证凭据，生成 JWT Token
5. 前端保存 Token 到 localStorage 和 Pinia Store
6. 检查路由 query 中是否有 redirect 参数
   - 有 → 跳转到 redirect 指定的页面
   - 无 → 跳转到首页 `/`

**特殊场景：**
- **从受保护页面跳转而来**：如果用户尝试访问需要登录的页面但未登录，会被重定向到登录页，登录后自动跳回原页面
- **Token 过期**：响应拦截器检测到 code 1004/1005，清除本地数据并跳转登录页

### 3. Token 管理

**存储位置：**
- `localStorage.accessToken` - JWT Token
- `localStorage.userInfo` - 用户信息（JSON字符串）
- Pinia Store - 运行时状态

**Pinia Auth Store 结构：**
```typescript
interface AuthStore {
  token: string              // 当前 Token
  userInfo: UserInfo | null  // 用户信息对象
  isLoggedIn: boolean        // 登录状态
  
  // Actions
  login(data: LoginRequest): Promise<{ success: boolean, message: string }>
  register(data: RegisterRequest): Promise<{ success: boolean, message: string }>
  fetchUserInfo(): Promise<{ success: boolean }>
  logout(): void
  initAuth(): void  // 从 localStorage 恢复状态
}
```

**初始化流程：**
```typescript
// main.ts
const authStore = useAuthStore()
authStore.initAuth()  // 应用启动时恢复登录状态
```

**initAuth 实现：**
```typescript
const initAuth = () => {
  const storedToken = localStorage.getItem('accessToken')
  const storedUserInfo = localStorage.getItem('userInfo')
  
  if (storedToken && storedUserInfo) {
    token.value = storedToken
    userInfo.value = JSON.parse(storedUserInfo)
    isLoggedIn.value = true
  }
}
```

### 4. Token 过期处理

**检测机制：**

**方式一：响应拦截器检测业务码**
```typescript
// request.ts
api.interceptors.response.use((response) => {
  const responseData = response.data as ApiResponse
  
  // 检测 Token 无效或过期
  if (responseData.code === 1004 || responseData.code === 1005) {
    handleTokenExpired()
    return Promise.reject(new Error(responseData.message))
  }
  
  return responseData
})
```

**方式二：HTTP 状态码检测**
```typescript
api.interceptors.response.use(null, (error) => {
  const status = error.response?.status
  
  if (status === 401) {
    handleTokenExpired()
  }
  
  return Promise.reject(error)
})
```

**过期处理流程：**
```typescript
const handleTokenExpired = () => {
  // 1. 清除本地存储
  localStorage.removeItem('accessToken')
  localStorage.removeItem('userInfo')
  
  // 2. 获取当前路径
  const currentPath = window.location.pathname + window.location.search
  
  // 3. 避免重复跳转
  if (!currentPath.includes('/login')) {
    router.push({
      path: '/login',
      query: { redirect: currentPath }
    })
    
    // 4. 显示友好提示
    ElMessage.warning('登录已过期，请重新登录')
  }
}
```

### 5. 路由守卫

**全局前置守卫：**
```typescript
// router/index.ts
router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('accessToken')
  
  // 检查目标路由是否需要登录
  if (to.meta.requiresAuth) {
    if (!token) {
      // 未登录，跳转到登录页并保存目标路径
      next({
        path: '/login',
        query: { redirect: to.fullPath }
      })
    } else {
      // 已登录，允许访问
      next()
    }
  } else {
    // 不需要登录的路由（登录/注册），直接放行
    next()
  }
})
```

**路由元信息配置：**
```typescript
{
  path: '/login',
  component: LoginView,
  meta: { requiresAuth: false }  // 不需要登录
},
{
  path: '/',
  component: Layout,
  meta: { requiresAuth: true },  // 需要登录
  children: [...]
}
```

### 6. 用户信息管理

**获取用户信息：**
```typescript
// auth.ts
export const getProfile = (): Promise<ApiResponse<UserInfo>> => {
  return api.get('/auth/profile')
}
```

**更新用户信息：**
```typescript
// auth.ts
export const updateProfile = (data: UpdateProfileRequest): Promise<ApiResponse<UserInfo>> => {
  return api.put('/auth/profile', data)
}

interface UpdateProfileRequest {
  nickname?: string
  email?: string
  avatar?: string
  currentPassword?: string  // 修改密码时需要
  newPassword?: string      // 新密码（可选）
}
```

**头像上传：**
```typescript
// auth.ts
export const uploadAvatar = (file: File): Promise<ApiResponse<{ avatarUrl: string }>> => {
  const formData = new FormData()
  formData.append('avatar', file)
  return api.post('/upload/avatar', formData, {
    headers: { 'Content-Type': 'multipart/form-data' }
  })
}
```

## 🔐 安全特性

### 1. JWT Token

**Token 结构：**
```
Header.Payload.Signature
```

**Payload 包含：**
- userId: 用户ID
- username: 用户名
- exp: 过期时间戳
- iat: 签发时间戳

**请求头格式：**
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 2. 密码安全

- 前端不存储明文密码
- 密码传输使用 HTTPS（生产环境）
- 后端使用 bcrypt 加密存储

### 3. XSS 防护

- Token 存储在 localStorage（而非 Cookie，避免 CSRF）
- 用户输入进行转义处理
- Element Plus 组件自动防御 XSS

## ⚠️ 注意事项

1. **不要在代码中硬编码 Token**
2. **生产环境必须使用 HTTPS**
3. **定期清理过期的 localStorage 数据**
4. **敏感操作需要二次验证（如删除账号）**
5. **Token 泄露应立即作废并重新登录**
